# Enterprise PowerPoint Design Guidance Template

> **Purpose**  
> Recreate the visual language, storytelling rhythm, and component system used in the reference presentations. This is a design system, not a content template. It is intended to let any presentation designer produce new slides that feel native to the same presentation family.

---

## 1. Design intent

The presentation style is a **dark, technology-forward enterprise system** with a bright green signal color, white message-led typography, sharp vector diagrams, selective photography, and disciplined information architecture.

The designer must aim for:

- **Executive clarity:** one primary message per slide.
- **Visual explanation:** diagrams, flows, scales, pathways, and data views before bullet lists.
- **High contrast:** charcoal backgrounds, white text, and controlled bright accents.
- **Structured energy:** thin lines, connected nodes, directional arrows, numerical steps, and asymmetrical compositions.
- **Technical credibility:** real system views, charts, process architecture, program status, and evidence.
- **Human readability:** large conclusions, restrained copy, predictable hierarchy, and generous negative space.

### North-star principle

> **Do not place content in a collection of boring boxes. Build a visual argument using vectors.**

Boxes are permitted only when they represent a real container, system boundary, data card, application screen, or comparison cell. Even then, reduce their visual weight and connect them to a larger composition.

## 2. Canvas and grid

### Slide format

- Ratio: **16:9 widescreen**
- PowerPoint size: **13.333 × 7.5 in**
- Design for projector and Teams readability.
- Keep all essential content inside a safe area of approximately **0.35 in** from every edge.

### Recommended grid

Use a 12-column grid with:

- Left/right margin: **0.45–0.60 in**
- Column gutter: **0.14–0.20 in**
- Top title zone: **0.55–1.05 in**
- Footer zone: **0.20–0.35 in**

Prefer intentionally uneven compositions such as 5/7, 4/8, or 7/5 columns. Avoid default three equally sized cards unless the logic genuinely contains three equal concepts.

### Alignment

- Align text, vectors, data labels, and screenshots to a shared grid.
- Use a strong left edge for most titles and explanations.
- Preserve one dominant visual axis per slide.
- Use spacing, rules, and vector connectors to establish grouping before adding containers.

## 3. Color system

### Core dark theme

| Role | Color | Hex | Use |
|---|---|---:|---|
| Primary background | Graphite | `#303034` | Default slide background |
| Alternate dark | Near black | `#1F2023` | Deep panels, high-contrast zones |
| Primary text | White | `#FFFFFF` | Titles, conclusions, key values |
| Secondary text | Cool light gray | `#E3E6EB` | Body copy and supporting labels |
| Tertiary text | Mid gray | `#A8ABB2` | Metadata, annotation, subdued labels |
| Muted text | Gray | `#6F7378` | Footnotes and low-emphasis copy |
| Primary accent | Signal green | `#00E676` | Key emphasis, active states, main paths |
| Alternate green | Bright green | `#00E487` | Use when matching legacy slides |
| Secondary accent | Electric blue | `#1F6BFF` | Secondary pathway or comparison |
| Cyan accent | Light cyan | `#39D8FF` | Tertiary pathway or learning stage |
| Warning | Orange | `#ED7D31` | Watch items, regional/local pathway |
| Caution | Amber | `#FFB300` | Limitations and attention |
| Risk | Coral red | `#FF6A5A` | Gaps, risks, negative status |

### Color rules

1. Green owns the primary story and should usually be the first accent the audience sees.
2. Blue introduces a secondary path, not decoration.
3. Orange or amber is reserved for exceptions, local alternatives, or warnings.
4. Red is used sparingly and only for material risk or failure.
5. Never use every accent on every slide.
6. For diagrams, repeat the same semantic color mapping across the whole deck.
7. Do not use low-contrast gray text for core messages.

### Light-theme exception

Some detailed matrix and curriculum slides use a white or very light content field with `#1F2023` text while retaining the same green/blue accent system. Use this only for dense reference slides, not as an alternating decorative treatment.

## 4. Typography

Use the organization-approved corporate sans-serif when available. If it is unavailable, use **Arial** or **Aptos** consistently. Do not mix font families.

### Type scale

| Element | Recommended size | Style |
|---|---:|---|
| Cover title | 30–38 pt | Bold, white |
| Section divider | 28–36 pt | Regular or semibold, white |
| Slide title | 22–28 pt | Bold, white |
| Eyebrow / kicker | 8–11 pt | Bold, uppercase, signal green |
| Subtitle | 12–16 pt | Regular, light gray |
| Body | 11–15 pt | Regular, white or light gray |
| Diagram label | 9–12 pt | Semibold where needed |
| KPI value | 24–34 pt | Bold, white |
| Footnote/source | 7–9 pt | Regular, muted gray |

### Typography rules

- Use sentence case for slide titles.
- Use uppercase only for short kickers, categories, statuses, and navigational labels.
- Emphasize only the decisive words in green, not full paragraphs.
- Titles must state the message whenever possible. Example: **“Four foundations turn AI capability into measurable supply-chain impact”**, not **“AI framework.”**
- Keep line length short. A title should normally fit into one or two lines.
- Do not use paragraphs longer than three lines on the slide.
- Do not shrink body text to rescue an overloaded slide. Reduce content or move detail to an appendix.

## 5. Signature visual language

### 5.1 Vector-first composition

Every analytical slide should have one dominant vector composition. Suitable vector forms include:

- Arcs that converge on an outcome
- Horizontal or vertical journeys
- Connected nodes and networks
- Stepped progressions
- Capability ladders
- Swimlanes
- Layered operating models
- Circular loops
- Quadrants
- Funnels
- Bridges from current to future state
- Branching trees
- Comparison scales
- Maturity curves
- Dependency maps
- Timelines with milestones

Vectors should be native PowerPoint shapes whenever feasible so they remain editable.

### 5.2 Vector styling

- Main path: **2.0–3.0 pt**, signal green
- Secondary connector: **1.25–2.0 pt**, light gray or blue
- Supporting rule: **0.5–1.0 pt**, muted gray
- Use rounded line caps.
- Use arrowheads only where direction is important.
- Prefer open structures and outlines over solid filled rectangles.
- Use glow, shadow, and gradient only when subtle and functionally meaningful.
- Keep line intersections clean. Do not let connectors pass through labels.

### 5.3 Icons

- Use one coherent outline-icon family.
- Use icons as semantic anchors, not decoration.
- Default icon treatment: green or white line icon, no tile behind it.
- If an icon needs a container, prefer a circle, clipped corner, or small outlined badge over a rounded rectangle.
- Keep icon stroke weights visually consistent with diagram connectors.

### 5.4 Photography

Photography is used selectively as a strong half-slide or full-bleed visual, especially for agenda, ambition, external perspective, and section-opening slides.

Use images with:

- Architectural or operational scale
- Technology overlays, networks, logistics, data, cities, facilities, or infrastructure
- Strong diagonal or radial composition
- Space that naturally supports the content layout
- Dark or neutral tones compatible with green accents

Do not use generic handshake photos, staged boardroom images, or unrelated “innovation” stock photography.

### 5.5 Screenshots

- Place application or SharePoint screenshots inside a clean device/window frame or a simple white outline.
- Crop tightly to the relevant interface.
- Add 1–3 vector callouts rather than explaining every interface element.
- Use screenshots as evidence, not as background decoration.

## 6. “No boring boxes and bullets” rule

### Replace default bullets with these patterns

| If the content is… | Do not default to… | Prefer… |
|---|---|---|
| Three strategic pillars | Three equal cards | A converging architecture leading to one ambition |
| A sequence | Numbered bullet list | A vector path with milestones and arrows |
| Current vs future | Two text boxes | A bridge, gradient continuum, or transition curve |
| Roles and ownership | Bullets by role | A swimlane or concentric operating model |
| Portfolio status | Long list | A maturity track, status spine, or impact/complexity map |
| Benefits | Bullets with bold numbers | KPI anchors tied directly to the value driver |
| Weekly program | Table | A cadence ribbon or repeating circular rhythm |
| Learning journey | Four cards | A staircase, progression path, or level map |
| Risk and mitigation | Two columns | Paired tension lines or risk-to-control connectors |
| Agenda | Bulleted contents | A navigational rail with highlighted active section |

### Maximum text convention

- Use no more than **3–5 short text fragments** around a dominant visual.
- If a diagram contains more than seven labeled elements, create levels of detail or divide it across slides.
- Bullets may remain in speaker notes or appendix slides.

### Box discipline

A box must earn its place by representing one of the following:

1. System boundary
2. Program or process stage
3. Data or KPI card
4. Application interface
5. Comparison cell
6. Governance boundary

Otherwise use position, whitespace, a line, a vector, a label, or an icon.

## 7. Core slide archetypes

### A. Cover slide

**Composition**

- Dark graphite canvas
- Thin green line across the top or at the title anchor
- Large title in the left third
- Small eyebrow above title
- Meeting name/date under title
- Optional oversized low-opacity keyword or acronym on the right
- Minimal author line near the bottom

**Do not:** add multiple logos, a collage, or a title inside a large box.

### B. Agenda / navigation slide

**Composition**

- Left: vertical green rail and compact agenda rows
- Right: strong full-height photograph or network visual
- Highlight current section in signal green
- Use thin separators rather than filled menu boxes

### C. Section divider

**Composition**

- Dark canvas
- One centered or left-aligned section statement
- Thin green bottom rule
- Optional small logo or classification footer
- No additional explanation

### D. Executive summary

Use a single visual logic such as:

- Journey from “Today” to “Transform”
- Platform ecosystem below the journey
- Groundwork, enablers, and next steps connected by directional flow

Avoid creating a mini-slide for every point. The summary should feel like one system.

### E. Framework / operating model

**Preferred formula**

1. Outcome or ambition at top
2. Three activation paths in the middle
3. Four enabling foundations underneath
4. Vector roof, arc, or arrows connecting foundations to impact
5. One conclusion sentence at the bottom

Use green, blue, and orange consistently for distinct delivery paths. Keep containers open and connect them to the overall model.

### F. Portfolio status

Use three zones:

1. Program purpose and progression
2. Use-case portfolio on a shared maturity spine
3. Focus area with accomplishments, next phase, and watch items

Anchor monetary or outcome KPIs at the bottom or right edge. Avoid a spreadsheet-style status table unless the slide is meant as a reference appendix.

### G. Timeline / reflection

- Use a strong left-to-right vector journey.
- Separate achievements from barriers using vertical position, color, or opposed arrows.
- Use circular numbered decision points for proposals and discussion questions.
- Show “where we are” directly on the timeline.

### H. Learning cadence

- Build a horizontal weekday rhythm with numbered nodes and arrows.
- Below it, show weekly progression using a staircase or continuous learning path.
- Make time requirements visual through proportion or repeated clock icons.
- Use evidence/output as the final node, not an extra bullet column.

### I. Process / approval flow

- Use a five-stage vector spine with numbered steps.
- Put role above or below each node and action as a short caption.
- Place cost and limitation information in a side rail.
- End with a visible approval gate or three-condition checklist.

### J. Capability gap / discussion slide

- Put existing strengths on one side of a tension line.
- Put missing capability or ownership on the other.
- Use “GAP” as the central visual hinge.
- Put discussion questions in a clear bottom band or open space.
- Avoid verdict-like visual language when the intent is discussion.

### K. Data and evidence slide

- Use one dominant chart or exhibit.
- Add a short takeaway directly beside or beneath it.
- Use green highlight only on the most important series or conclusion.
- Put source details in the bottom-right footnote area.
- If showing external evidence, separate source material visually from internal interpretation.

### L. Use-case landscape

- Use an impact-versus-complexity matrix, maturity curve, or bubble map.
- Encode type with color and estimated value with bubble size only when both measures are reliable.
- Keep a compact legend.
- Label only priority items on the main slide; list all cases in the appendix.

### M. Closing / discussion slide

- One provocative question or decision statement
- Large type, centered or strongly left aligned
- Optional subtle image or vector signal
- No summary bullets unless strictly required

## 8. Charts and data visualization

### General rules

- Use editable PowerPoint charts or vector shapes.
- Remove chart borders, unnecessary gridlines, and redundant legends.
- Direct-label data whenever practical.
- Highlight one series in green; render context series in gray.
- Use white chart areas only when matching an imported exhibit or when dense data requires a light field.
- State the conclusion in the title or an adjacent takeaway.
- Display units, period, and source.

### Recommended chart choices

- Trend: line chart
- Comparison: horizontal bar chart
- Progression: milestone line or maturity curve
- Benefit bridge: waterfall
- Portfolio prioritization: 2×2 or bubble plot
- Composition: stacked bar
- Status: vector maturity spine, not a traffic-light table
- Process: arrows and nodes, not SmartArt defaults

### KPI treatment

- Place KPI value first, label second, context third.
- Use large white numerals.
- Use green for favorable impact, blue for cash/capability, and orange/red for watch/risk.
- Connect KPIs to the exact use case or driver using a line or spatial alignment.

## 9. Content hierarchy and writing

### Slide writing formula

1. **Kicker:** section or category
2. **Title:** message or decision
3. **Subtitle:** one-sentence context, if needed
4. **Visual body:** the argument
5. **Takeaway:** final implication or action
6. **Source/footer:** evidence and classification

### Voice

- Direct, concise, and evidence-led
- Strong verbs
- Minimal jargon unless the audience uses it
- Business impact before technical detail
- Use questions intentionally for discussion slides

### Editing limits

- Title: ideally under 12 words
- Subtitle: ideally under 20 words
- Diagram label: 2–6 words
- Explanatory text: 1–2 lines per element
- Takeaway: one sentence

---

## 10. Footer and classification

Use a restrained footer system:

- Classification in muted gray at bottom-left
- Slide number in muted gray at bottom-center or bottom-left
- Source or short reference at bottom-right
- Optional small brand mark at bottom-right
- Never let the footer compete with slide content

When source citations are required, use **7–9 pt** text and a short label. Move long URLs to speaker notes or a reference slide.

---

## 11. Motion and builds

Use animation only when it improves comprehension.

Recommended:

- Appear or fade for progressive disclosure
- Wipe along the direction of a process arrow
- Morph between current and future state
- Sequential reveal of maturity stages

Avoid:

- Bounce, spin, fly-in from arbitrary directions
- Multiple animation styles on one slide
- Animating every icon or word

A slide should still communicate correctly when printed or exported to PDF.

---

## 12. Accessibility

- Maintain strong text/background contrast.
- Do not encode status with color alone; add label, symbol, or position.
- Minimum body text: **11 pt**, with **12–15 pt** preferred.
- Add alt text to meaningful images and diagrams.
- Keep reading order logical.
- Avoid red/green-only comparisons.
- Use meaningful link labels instead of raw URLs.

---

## 13. Designer workflow

### Step 1: Define the message

Write one sentence answering: **What should the audience understand, decide, or do after this slide?**

### Step 2: Choose the visual grammar

Select one: path, loop, layers, bridge, staircase, matrix, network, hierarchy, flow, chart, or photographic split.

### Step 3: Sketch the vector story first

Build the visual skeleton before writing body copy. Use lines, nodes, arcs, arrows, and labels.

### Step 4: Place evidence

Add the data, screenshot, source, status, or KPI that proves the message.

### Step 5: Add minimal explanatory text

Only include words needed to understand the visual.

### Step 6: Apply the design system

Use the approved palette, typography, line weights, grid, and footer.

### Step 7: Test at thumbnail size

The intended hierarchy and dominant message must remain evident when the slide is viewed as a thumbnail.

### Step 8: Test in presentation mode

Check legibility, pacing, visual balance, and whether the presenter has a clear talk track.

## 14. Quality-control checklist

### Story

- [ ] The title communicates the conclusion or purpose.
- [ ] The slide contains one primary message.
- [ ] The visual supports the message instead of decorating it.
- [ ] The audience knows what matters and what happens next.

### Vector-first design

- [ ] A vector composition was considered before boxes and bullets.
- [ ] Connectors show real relationships or direction.
- [ ] Shapes remain editable.
- [ ] The slide does not look like a grid of unrelated cards.
- [ ] Lines do not cross labels or terminate ambiguously.

### Visual system

- [ ] Graphite, white, gray, and signal green dominate.
- [ ] Accent colors have consistent meaning.
- [ ] Typography follows the size hierarchy.
- [ ] Alignment and spacing follow the grid.
- [ ] Icons come from one family.

### Content

- [ ] Text is concise and readable.
- [ ] Confirmed facts are separated from assumptions.
- [ ] Numbers show units and time periods.
- [ ] Sources are present where needed.
- [ ] Dense supporting detail is moved to the appendix.

### Technical quality

- [ ] Objects do not overlap accidentally.
- [ ] No text is clipped or too small.
- [ ] Images are high resolution.
- [ ] Charts and vectors are editable when practical.
- [ ] Colors work in presentation and PDF export.
- [ ] Footer and classification are consistent.

---

## 15. Anti-patterns

Never use:

- A page full of equal rounded rectangles
- Long bullet lists copied from source documents
- Default PowerPoint SmartArt without redesign
- Decorative icons that do not carry meaning
- Multiple unrelated stock images
- 3D charts
- Heavy drop shadows
- Random gradients
- Rainbow color coding
- Tiny legends or footnotes
- Center alignment for dense business content
- A table when a relationship, flow, or comparison is the real message
- A title that only names the topic when a conclusion is available

## 16. Reusable specification for a designer or AI presentation tool

```text
Create a 16:9 enterprise PowerPoint slide in the reference style.

Visual language:
- graphite background #303034
- white titles and key values
- light-gray supporting text #E3E6EB
- signal-green primary accent #00E676
- blue #1F6BFF for a secondary path
- orange #ED7D31 only for warning or regional/local distinction
- crisp sans-serif typography
- thin green top rule or visual anchor
- restrained footer with classification, source, and slide number

Composition:
- one message-led title
- one dominant editable vector composition
- use lines, paths, nodes, arrows, arcs, or layered structures
- do not use a collection of generic boxes
- replace bullets with a flow, progression, comparison, network, or capability model
- preserve generous negative space and strong grid alignment
- use photography or screenshots only when they provide evidence or narrative scale

Content:
- one primary idea
- 3–5 short labels or statements at most
- one explicit takeaway, action, or decision
- factual claims sourced in a footer or speaker notes

Quality:
- readable at presentation distance
- no accidental overlaps
- no clipped text
- consistent semantic colors
- editable vectors and charts where practical
```

## 17. Reference character summary

The two reference decks share the following recognizable DNA:

- Dark charcoal canvas and bright green brand signal
- White, bold, compact titles
- Green uppercase kickers
- Thin rules and directional vector language
- Split layouts pairing structured content with a large image or exhibit
- Section dividers with minimal text
- Frameworks that connect foundations, pathways, and outcomes
- Status and financial impact shown within the same visual system
- Selective use of blue, cyan, orange, amber, and red for semantic distinctions
- Footer-level classification and sourcing
- A transition from older, denser boxed layouts toward more open, executive, vector-led storytelling

Use this system consistently so that newly created slides look as though they belong to the same presentation family, while improving clarity by making vectors, relationships, and narrative flow the default.
